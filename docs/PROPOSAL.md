# 基于 Hy3 的财务表格推理过程评估与错误定位方案

## 一、项目概述

本项目面向“可验证场景中的过程评估与错误定位”任务，选择财务报告表格问答作为应用场景。系统向 Hy3 提供财务报告中的文字、表格和计算问题，要求模型给出使用的证据信息、分步计算过程、中间结果和最终答案。在完成答案校验的同时，系统进一步判断计算过程是否成立，定位最早出现错误的步骤，并给出错误类型。

项目使用 FinQA 作为主要数据来源。FinQA 中包含财务报告文字、表格、问题、标准证据、标准计算程序和标准答案，能够支持自动计算和结果核对。

项目最终形成一套可以运行和复查的评测流程，用于观察 Hy3 在财务数据理解、证据选择、多步计算和结果表达方面的表现，并验证过程评估器能否准确发现和定位错误。

## 二、设计思路

财务表格问题的答案通常由若干证据和计算步骤共同得到。例如，计算收入增长率时，需要先找到两个年份的收入数据，再依次完成差值、除法和百分比换算。只检查最终数值无法判断模型是否使用了正确数据，也无法发现错误步骤被后续计算抵消的情况。因此，本项目将一次解答拆分为证据选择、计算步骤和最终答案三个可以分别检查的部分。

Hy3 按统一格式输出解答。每个步骤记录当前运算、输入数据、引用的上一步结果和本步计算结果，使模型给出的方案能够被程序读取和执行。系统不要求固定自然语言表述，只要求关键证据和运算关系可以被复核。

| 输出内容 | 具体含义 |
| --- | --- |
| 证据信息 | 回答问题所使用的表格行、单元格或报告文字 |
| 计算步骤 | 按顺序记录运算类型、操作数及步骤依赖 |
| 中间结果 | 每一步计算得到的数值及必要的单位或百分比说明 |
| 最终答案 | 模型给出的最终数值或百分比结果 |

最终答案和推理过程采用独立判定。最终答案通过数值比较和百分比换算规则进行校验；推理过程则依次检查证据是否正确、操作数是否来自相应证据、运算符是否合适、步骤依赖是否成立以及中间结果是否正确。评估器按照步骤顺序输出第一个错误位置，不用最终答案反推前面的过程正确。

为了验证评估器本身是否可靠，项目在标准计算程序的基础上构造受控错误样本。每次只修改一个主要环节，例如替换证据、改变操作数、将除法改为乘法、遗漏百分比换算或打乱步骤依赖。由于修改位置和方式都是预先记录的，这些样本可以直接提供首错位置和错误类型标签。

## 三、系统架构

系统按照“数据准备—解答生成—过程解析—自动验证—结果展示”的流程运行。FinQA 题目首先被整理为统一的数据格式，Hy3 根据题目生成结构化解答，解析模块提取证据和计算步骤，验证模块执行计算并逐步检查过程，最后生成单题报告和整体实验结果。

| 层次 | 主要模块 | 主要功能 |
| --- | --- | --- |
| 数据层 | FinQA 数据读取与样本整理 | 读取报告文字、表格、问题、标准证据、标准程序和答案 |
| 生成层 | Hy3 解答生成器 | 生成证据、分步计算、中间结果和最终答案 |
| 解析层 | 结构化结果解析器 | 检查输出完整性，提取步骤和步骤之间的引用关系 |
| 验证层 | 证据检查与计算执行器 | 核对证据来源，执行计算程序，比较中间结果和最终答案 |
| 评估层 | 过程评估与错误定位器 | 判断过程是否正确，定位第一个错误步骤并分类 |
| 展示层 | 单题报告与统计结果 | 展示判定依据、典型案例、指标和难度分层结果 |

数据、模型原始输出和评估结果分别保存，并通过样本编号关联。这样可以在不重新调用模型的情况下调整解析或评价规则，也便于复查某一道题的完整过程。

## 四、评测题集设计

项目从 FinQA 公开数据中选择 30 道具有完整标准信息的题目。题目按照标准计算程序的步骤数量和证据来源进行分层：简单题以单一表格证据和一步计算为主；中等题包含两步计算或多个数据项；困难题包含三步及以上计算、文字与表格联合取数或较复杂的百分比关系。

评测材料共包含 90 个过程样本，其中 30 个为标准正确过程，另外 60 个由标准程序生成受控错误。错误样本覆盖证据引用错误、操作数错误、运算符错误、步骤依赖错误、百分比或单位处理错误，以及最终答案正确但过程不成立等情况。样本分别保存题目、标签和首错位置，支持逐例核验。

| 样本组成 | 数量 | 用途 |
| --- | --- | --- |
| FinQA 题目 | 30 道 | 覆盖不同证据来源、运算类型和计算步数 |
| 正确过程 | 30 个 | 测量评估器对正确过程的误报情况 |
| 受控错误过程 | 60 个 | 测量错误检出、首错定位和错误分类能力 |

## 五、重点技术

**结构化解答生成。** 通过统一提示词约束 Hy3 输出证据、运算步骤、中间结果和最终答案。解析器对字段完整性和步骤编号进行检查，格式不完整的回答单独记录，不直接计为过程正确。

**证据来源核对。** 将模型引用的表格行、数值和文字片段与题目上下文及 FinQA 标准证据进行对应，判断计算所使用的数据是否确实来自题目提供的材料。

**计算程序执行。** 实现加、减、乘、除、百分比换算等 FinQA 常用运算。执行器按照步骤依赖计算每个中间结果，使算术错误和依赖错误能够由程序直接发现。

**首个错误定位。** 评估器按照证据、操作数、运算、步骤依赖、中间结果和最终答案的顺序检查。某一步首次不满足要求时，记录该步骤为首错位置，并区分本步产生的错误与从前一步继承的错误。

**受控错误生成。** 从标准计算程序出发，对证据、操作数、运算符、步骤顺序和比例换算进行单点修改。每个错误样本保存修改位置、错误类型和预期首错，使评估器的定位结果可以与真实标签直接比较。

**过程与答案一致性检查。** 分别判断最终答案是否正确、计算过程是否正确，并检查最终答案能否由当前过程实际得到。这样可以识别直接填入标准答案、使用错误证据但碰巧算对，以及中间步骤错误后结果又回到正确值等情况。

## 六、评价指标与预期效果

项目使用最终答案准确率观察 Hy3 完成财务问题的基本效果，使用过程正确率、错误检出率、首错定位准确率和错误类型准确率评价过程评估能力。对正确过程单独统计误报率，对“最终答案正确但过程错误”的样本统计识别率。

| 指标 | 说明 |
| --- | --- |
| 最终答案准确率 | Hy3 最终答案与标准答案一致的样本比例 |
| 过程正确率 | 证据和全部计算步骤均成立的样本比例 |
| 错误检出率 | 受控错误样本中被评估器正确发现的比例 |
| 首错定位准确率 | 评估器给出的第一个错误位置与标签一致的比例 |
| 错误类型准确率 | 错误类别判断与预设标签一致的比例 |
| 正确过程误报率 | 正确过程被错误判定为存在问题的比例 |

预期完成一个支持单题演示和批量评测的应用。单题结果能够展示模型所用证据、计算步骤、每一步判定、首错位置和错误类型；批量结果能够按照题目难度和错误类型统计整体表现。最终交付项目代码、评测数据、运行脚本、完整实验结果、典型案例分析和两分钟以内的演示视频。
